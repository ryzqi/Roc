# 仓库只维护一套前端

## 决定

Renderer 只有 `src/renderer/` 一套实现，入口为 `AppShell` 与项目门户。不保留第二套壳、临时前端选择变量、旧视图或 testid 别名。新增项目能力必须进入现有面表、助手或检查器。

前端切换采用入口、目录与测试同步变更，避免代码和检查分别绑定两套界面。后端 IPC 合同独立维护；前端通过受限 preload API 使用能力。

界面偏好统一经过 `ui-state.ts`，使用 `roc.ui.` 命名空间；路由、偏好字段、测试命名与懒加载边界由[工作台合同](../research-workbench.md)维护。

## 理由与代价

双壳需要同时维护 DOM、样式、路由和测试，容易使功能改到错误入口。单壳使导航与能力归属明确，但旧页面断言需要用当前交互重新表达；无法直接复用旧 testid。

当前检查入口见[开发指南](../development.md)。
