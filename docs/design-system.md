# Roc 任务导航与组件设计契约

本契约将《Roc UI/UX 全面重构方案》落实为可核对的界面结构。它规定目标行为，不代表用户访谈、真实下载、模型运行或可访问性验收已经通过。工程检查与真人任务测试分别记录，不以演示数据替代运行结果。

## 单壳与导航

继续使用 [AppShell](../src/renderer/app/AppShell.tsx)，栏序为 **左栏 | 画布 | 右侧助手**。助手按需打开，关闭助手保留会话、运行及输入草稿；运行和待批准状态仍能从顶栏进入。设置、搜索与 Git 复用既有浮层，任务中心使用会话与任务画布，不新增第二个壳或项目外路由。

能力分类由 [surfaces.ts](../src/shared/surfaces.ts)维护，当前四个活动栏目的地由 [routes.ts](../src/renderer/app/routes.ts) 和 [AppNavigation.tsx](../src/renderer/shell/AppNavigation.tsx)映射。发现和知识作为子视图，历史 URL 在路由入口集中转换。

| 目的地 | 路由视图 | 主对象与默认动作 | 次级能力 |
| --- | --- | --- | --- |
| 工作台与发现 | `overview` | 项目目标、未完成任务和近期成果；继续研究 | 最近会话、需要处理的项目事项 |
| 发现子视图 | `overview&subview=discover` | 学术候选；搜索并选择加入文献库 | 推荐与趋势、保存检索、追踪 |
| 文献与知识 | `library` | 已收录文献；阅读或添加文献 | 笔记、引用、全文处理和元数据 |
| 知识子视图 | `library&subview=knowledge` | 已有资料的证据；问我的资料 | 知识页、图谱、索引诊断 |
| 写作 | `writing` | 文稿；继续编辑、编译与导出 | 主文件、引用、构建问题、Git、终端 |

会话与任务（`runs`）是第四个活动栏目的地，聚合会话与任务中心。终端在写作中打开；记忆、技能、外部工具连接和诊断复用管理抽屉。侧栏文件、文献和会话属于项目上下文；切换目的地保留选择状态。

### 窗口与焦点

- 主窗口最小宽度来自 [chat-layout.ts](../src/shared/chat-layout.ts)，当前为 1184px。1440px 起且画布至少保留 760px 时可同时内联左栏、画布与助手；1100–1439px 保留左栏与画布，助手覆盖；1099px 及以下两侧面板均为抽屉。默认左栏 232px、助手 344px；较宽的手动面板会触发助手覆盖。1184、1280、1440px 是实机检查尺寸，不是三套页面。
- 打开导航抽屉或助手抽屉不改变当前画布对象。关闭后焦点返回触发控件；Escape 只关闭顶层可关闭浮层。未保存表单沿用导航保护，待确认操作不因尺寸变化被清空。
- 浮层栈在布局阶段登记归属。设置的 Radix Dialog 继续负责焦点陷阱、Tab 和无障碍语义；只有不含内部弹出控件的确认框启用 Roc 栈顶 Escape 捕获，避免确认框已经获得焦点、Radix 的旧父层监听器却尚未交接。首次聚焦时的 Escape 同样只取消确认，保留设置草稿；退出动画期间继续阻止键盘作用于底层。设置表单和远端模型选择器沿用 Radix 的 Escape 路径，不扩大捕获到含 select 或自管 popover 的表单。
- 窗口红绿灯、标题栏拖动区、文本选择和原生滚动保持 Electron 原生语义。按钮区域设置 `no-drag`；页面外层不横向滚动，代码、宽表格和终端只在各自容器内滚动。
- 主内容宽度不足时先收起辅助面板，不缩小字体。阅读器和编辑器保留当前滚动与编辑位置。
- 原生缩放导致 CSS 视口高度不超过 400px 时，两套模态壳统一取消外投影并缩减外部留白，面板负责滚动，正文与底部确认动作保持原字号和目标尺寸。设置在宽度不超过 719px 的短视口中，将分区导航、表单与保存栏交给同一滚动容器；活动栏高度不足时独立滚动。确认仍默认聚焦取消，取消保留草稿，明确确认后才保存或放弃，尺寸适配不改变关闭守卫。[设置与共用确认回归](../tests/renderer/radix-settings-dialog.test.mjs)覆盖真实 400% 原生缩放下保存/放弃的完整按钮与回执，并检查控件、焦点环和五点命中可见性。

## 对象、动作与状态归属

| 对象 | 身份与权威来源 | 主动作 | 唯一落点 |
| --- | --- | --- | --- |
| 项目 | `projectId`，项目 store/IPC | 打开、继续研究、切换 | 工作台与项目作用域 |
| 文献 | `itemId`，共享 literature store | 阅读、补充全文、解析 | 文献详情/阅读器 |
| PDF 与解析结果 | 文件协议、parse 回执 | 阅读、定位片段、重试解析 | 该文献阅读器 |
| 笔记与知识页 | 原有笔记/Wiki 记录 | 编辑、查看来源、提问 | 文献笔记或知识工作区 |
| 会话与 Agent 运行 | `threadId`、`runId`、现有运行快照 | 继续、停止、批准或拒绝 | 助手及同一任务详情 |
| 后台任务 | 原任务 ID、处理回执 | 查看、取消、按能力重试 | 共享任务中心的对应类型 |
| 成果文件 | 项目 ID、工作区相对路径 | 打开、检查差异、导出 | 原文件预览或写作编辑器 |

任务中心位于 `runs`，聚合各权威来源的摘要，不建立第二份持久化任务表。组件由稳定对象 ID 识别内容，不能用标签可见性决定草稿身份。菜单、搜索结果、工作台摘要调用同一对象打开动作；权限校验仍在实际执行通路发生。

文献显示五段事实：**论文信息 → 全文 → 解析 → 索引 → 知识页**。每段使用实际记录的文字状态；不存在记录时显示“未获取”“未解析”“未索引”或“不适用”。元数据成功不推出全文成功，解析成功不推出索引成功。没有可靠调度和回执的步骤提供真实下一步，不用计时器推进。批量回执区分成功、重复跳过、需要处理和失败。

Agent 区分草稿、已受理、执行中、等待批准、已完成、失败及已停止；发出停止请求与收到停止回执分别表达。重试或恢复只调用已有能力，保留已经产生的结果和副作用说明。

## 页面骨架与十个关键状态

工作台、发现、文献、知识、写作与任务中心分别选用工作台、搜索列表、列表与详情、搜索与证据、编辑工作区和标准条目列表骨架。页面标题在内容容器外；查询页遵循 `PageHeader → FilterPanel → DataSection → BulkActionBar`。编辑器不强套查询模板，工作台不为装饰增加统计图。

以下为持久的结构规格。`[主: …]` 表示当前区域唯一主操作；`[…]` 为中性次操作；括号内状态必须来自真实数据。

### 1. 空项目

```text
项目名                                      [主: 开始研究]
研究目标（仅已有目标时展示）
尚无文献                                    [添加文献]
检索论文    导入 PDF    问我的资料    打开写作
```

首次引导最多三步，可跳过，可从帮助再次打开；不要求先填写全部模型或工具设置。能力缺失仅提示当前动作所需设置。

### 2. 有待办的工作台

```text
项目名                                      [主: 继续研究]
当前任务     任务标题 / 实际阶段              [查看任务]
待处理       最多三条对象与原因               [查看全部]
近期成果     文献、笔记、文稿标题              [打开对象]
```

继续按钮指向实际可恢复任务；没有可恢复任务时显示开始动作。近期成果链接真实对象，不能把聊天文本当作已保存文件。

### 3. 检索中的发现页

```text
发现
主题或关键词                         [查询中，禁止重复提交]
时间范围    来源    其他筛选
来源 A：检索中    来源 B：已返回    来源 C：受限 [详情]
已返回的候选列表
```

查询显式提交；筛选最多四项常驻。部分来源失败时保留有效结果并显示失败来源，不将其标为全部完成。

### 4. 候选列表与批量回执

```text
发现                         结果总数
选择  标题 / 作者 / 年份       来源 / 全文 / 是否已收录
[候选摘要在旁或同页展开]
已选 N 篇                                   [主: 加入文献库]
回执：成功 N 篇 / 重复 N 篇 / 需要处理 N 篇 / 失败 N 篇
```

重复项目明确标记“已在文献库”；回执可下钻。添加动作保留候选选择与当前查询。

### 5. 文献列表与阅读

```text
文献                                        [主: 添加文献]
搜索    标签    排序
文献列表                  标题 / 全文状态 / 知识可用状态
                          阅读器工具栏
                          PDF 或结构化全文
                          [笔记] [引用] [更多]
```

阅读和笔记共享选中文献，不重新建立选择 store。文献工具栏分为搜索/导入与排序/筛选/批选两层，归档筛选按需展开。条目优先展示标题、作者与年份，只有选中项展示已读取的全文状态；不从列表元数据推断索引。超过 60 条时动态加载已安装的 Virtuoso，按可见范围挂载行；原生按钮配合上下方向键、Home/End 导航，排序、外部选择和手动滚动后保留可进入的键盘焦点。手动滚动卸载焦点行时，焦点回到列表容器，不反向滚动；方向键可继续导航。窄画布先收起列表；返回列表恢复筛选与选中对象。

### 6. 添加文献与未获取全文

```text
添加文献
从 PDF    从 DOI/链接    从学术搜索    从 Zotero/引用文件
[其他方式：手工录入]
所选方式的单一表单                          [主: 添加文献]
回执：已保存论文信息，尚未获取全文           [获取全文]
```

六条原有导入通路保持原语义。表单禁用遮罩关闭；更换方式或关闭时保护未提交输入。链接仅接受后端支持的类型，不以 UI 文案扩张导入能力。

### 7. 处理失败

```text
文献标题
信息：已收录    全文：已保存    解析：失败    索引：未建立
失败原因与受影响阶段                        [主: 重试解析]
[打开 PDF] [查看处理回执]
```

重试限于失败且后端可重入的阶段；原因无法确定时显示实际错误并给出手动处理出口。内部 ID 和凭证在详情中按需展开。

### 8. 知识问答与证据

```text
知识
问我的项目资料                              [主: 提问]
工作区可检索文件数（仅该索引范围）           [管理索引]
助手生成回答
支持证据：文献标题 / 页码或片段              [打开证据]
可继续探索
[知识页 → 关系图] [索引诊断]
```

提问先执行真实检索，再复用助手回答通路；证据列表留在知识画布，答案在助手生成。工作区索引计数不代表项目全部文献，不展示没有权威来源的总数。没有证据时明确显示不足，不生成虚假引用跳转。未索引状态提供处理入口；引用打开原文定位并保留问答上下文。

### 9. 写作与构建问题

```text
写作    当前主文件                           [主: 编译]
[正文] [PDF 预览] [引用] [更多工具]
编辑正文                   可选预览
构建问题：文件 / 行号 / 原因                 [定位问题]
已生成 PDF                                  [导出 PDF]
```

编译与导出按当前状态确定主次，不并列强调；编译中锁重复触发。保持 CodeMirror 草稿、原主文件和既有输出路径；终端与 Git 由工具入口打开。

### 10. 助手审批、结束与任务中心

```text
顶栏：执行中 N / 待批准 N                    [任务中心]
当前任务     目标 / 最近实际进展              [停止]
待批准       动作 / 目标 / 影响 / 后果         [允许] [拒绝]
结束摘要     已完成 / 未完成 / 实际成果        [打开成果]
详情         时间线 / 原因 / 回执              [技术信息]
```

允许和拒绝视觉权重相同，审批不自动抢焦点。任务中心按当前、待处理、最近结束与失败分类；任务摘要、助手、后台处理列表必须指向同一记录。失败、拒绝、停止保留已有成果，恢复只在真实能力可用时显示。

所有数据区覆盖正常、空、加载、错误、受限五态。空状态仅给一个主要下一步；关键错误原因和批准影响不能藏入 tooltip。

## 深链与历史导航

[routes.ts](../src/renderer/app/routes.ts) 是唯一 URL 规范化入口。新写出的 URL 只使用规范目的地；历史值只在输入边界迁移，不在组件里再建旧页分支。

| 输入 | 规范落点 | 必须保留 |
| --- | --- | --- |
| 项目内未提供 `view` | `overview` | 项目作用域 |
| `view=latex` | `writing` | 相对文件路径、助手开关 |
| `view=literature` | `library` | 项目与共享文献选择 |
| 旧文献检索/知识子页请求 | `library&subview=knowledge` 对应内容 | 问答、知识页或证据选择 |
| 旧文献雷达/监控请求 | `overview&subview=discover` 对应内容 | 原查询或追踪对象 |
| `view=terminal` | `view=writing&tool=terminal` | 项目、工作目录和返回路径 |
| `view=memory/skills/mcp` | `view=overview&tool=memory/skills/mcp` | 项目与管理分区 |
| 未识别或尚无 UI 的能力 | 明确未提供的落点 | 不谎称已打开该能力 |

工具参数接受 `files/git/terminal/memory/skills/mcp/tasks`；`tool=tasks` 规范化为 `view=runs` 并移除工具参数，终端只在写作上下文打开，其余管理分区复用同一抽屉。旧子页若从未编码到 URL，则消费原有共享导航请求，不虚构历史参数。文献、概念和证据使用一次性对象导航命令，保留稳定 ID 与定位信息，草稿守卫接受后才切换对象。规范化后的 `parse(write(route))` 保持相同项目、文件和浮层状态；Back/Forward 同样经过草稿保护。

迁移分支只支持上一版确实产生过的入口，并用集中测试记录。新入口、内部链接和验证脚本同步改为新 ID；确认迁移窗口结束后统一删除映射，不能长期保留两套页面。

## 视觉、组件与 Do/Don't

使用现有 [tokens.css](../src/renderer/styles/tokens.css)、[motion.ts](../src/renderer/shared/motion.ts) 和系统字体。圆角 6/8/12/16，正文 13px，chrome 与元数据 12px；同屏不超过四档字号。阅读角色使用既有阅读 token，不整体放大操作区。

间距使用 4px 网格。新增页面间距、可读宽度、导航宽度和检视器宽度均定义为语义 token；不另建主题。面板默认无阴影，0.5px 微边框分隔；浮层外层承担阴影、内层承担圆角裁切。嵌套圆角按内边距保持同心，不能随意引入第五档圆角。保留项目约定的类别图标色相，操作强调色只有一个。

| 组件/场景 | Do | Don't |
| --- | --- | --- |
| 页面导航 | 从 surface 分类产生目的地，当前项带文字和选中语义 | 把专业工具扩成一级标签或复制另一份导航表 |
| 页头 | 标题、真实对象摘要、一个主操作 | 叠卡片、大写悬顶标签、宣传式副标题 |
| 按钮 | 默认、悬停、按下、禁用、加载、可见焦点六态；异步动作转圈并锁点击 | 固定文字按钮宽度、重复提交、移除焦点外框 |
| 表单 | 复用 `shared/form-ui.tsx`，标签置顶，错误贴近字段 | 无 label 的占位符表单、把验证错误放全局弹窗 |
| 表单浮层 | 复用 `ModalShell`，显式 `closeOnBackdrop={false}`，接入 `beforeClose` | 引入另一套弹窗库，点击遮罩静默丢草稿 |
| 破坏性操作 | 复用 `ConfirmDialog`，对象、后果和明确动宾按钮 | “确定吗”、危险按钮默认聚焦、仅颜色提示危险 |
| 详情/来源 | 同页展开或既有抽屉，保留列表上下文 | 查看一条来源就创建新整页或抽屉套抽屉 |
| 状态与阶段 | 浅底文字徽标、真实阶段、原因和可行动的恢复入口 | 彩虹状态、深色底、只靠颜色、假百分比 |
| 空与失败 | 复用 `EmptyState`、`ErrorBar`；一个主要出口 | 演示数据填空、笼统“操作失败”、关键原因折进 tooltip |
| 证据和产物 | 绑定真实 ID、页码或相对路径，调用既有打开动作 | 任意拼接文件 URL、Blob PDF、假文件卡片 |
| 分隔与文案 | 间距、细线与灰阶；必要说明按需披露 | 中点分隔符、左缘彩条、冗余常驻说明 |
| 数值与阅读 | 数值 `tabular-nums`，计数带单位，标题 `text-wrap: balance` | 裸数、跳动数字、小于 12px 字体、削掉音标 |
| 方向与动效 | 逻辑属性；代码、日志、进度与数字保持 LTR；尊重 reduced motion | 为装饰新增动画或整体镜像终端 |

`closeOnBackdrop={false}` 是本项目 `maskClosable={false}` 的等价契约；不为适配术语更换组件。Loading 仅说明已经发出的操作，不能自动认定成功。暗色主题由字号角色和字重 token 补偿；不在页面散写主题覆盖。

### 受控操作按钮（2026-11-23 P1.1）

`shared/form-ui.tsx` 的 `ActionButton` 复用现有三种按钮类：`primary` 为保存/提交，默认 `secondary` 与输入框同高，`compact` 用于紧凑工具栏。调用方传入真实 `loading` 和可选 `loadingLabel`；加载时显示 Lucide 指示图标、设置 `aria-busy` 并原生禁用，普通禁用不显示进行中。悬停、按下、禁用、键盘焦点沿用原样式，按下位移与转圈遵守 reduced motion。

组件只渲染受控状态，防重锁、错误、成功回执和焦点恢复仍属于业务流程。默认 `type="button"`；显式 `type="submit"`、`form`、`name/value`、`ref`、ARIA 和原生 disabled fieldset 语义完整透传。不要在此组件内另建异步任务状态、自动重试或审批决策。加载文案必须描述实际操作，不得提前显示“已保存”。

首批用于模型设置的保存密钥、测试连通，以及设置保存栏。保存栏的 `busy` 锁住保存与放弃；只有 `saving` 显示“保存中”，两者不可合并。`ConfirmDialog` 继续保留其确认锁、取消初焦点和关闭保护。

[永久组件夹具](../tests/renderer/fixtures/action-button-gallery.tsx)使用模型设置内容展示六态；[Electron 回归](../tests/renderer/action-button.test.mjs)编译当前 CSS，驱动真实 hover、press、Tab 和原生表单提交。它仅属于测试，不注册产品路由；截图可通过 `ROC_UI_AUDIT_DIR` 输出到临时目录供审阅。

助手输入沿用 IME 守卫、草稿隔离和消息跟随控制。用户上滚时停止自动跟随，提供返回底部入口。附件过渡、骨架屏和流式反馈沿用共享动效方案；不绕过减少动效设置，不使用动效延迟伪造运行进度。

### 共享表单反馈与只读（2026-11-23 P1.2）

`TextField`、`NumberField` 与 `SelectField` 用独立标签作为可访问名称；说明和当前错误通过唯一 ID 组成 `aria-describedby`，错误同时设置 `aria-invalid`，并显示图标与文字。错误消失时同步移除关联。`CheckboxField` 的说明属于描述，不拼入名称；整个标签仍可点击切换。

文本和数值字段的 `readOnly` 使用原生属性和可见“只读”标记，可聚焦与选择；文本可用系统复制快捷键。不能用 `disabled` 代替稳定标识的只读状态。真正不能操作的提交等待仍使用原生 `disabled` / `fieldset disabled`，不参与 Tab 导航；Select 与 Checkbox 不虚构只读属性。

`NumberField` 保留本地文本，失焦或 Enter 才提交；空值按调用方契约映射为 `undefined` 或 `null`，零仍为零。提交前检查自身只读/禁用及祖先 fieldset 禁用，并复用 `useImeGuard` 避免输入法确认键触发业务提交。字段不新增截断、范围校正或第二套校验规则。

模型设置读取既有 `validateDraft` 结果，将名称、类型、地址、模型标识/显示名和可编辑高级数值的错误关联到字段。供应商索引每次按 ID 重新定位；高级数值首次出现错误时展开，修正后保持展开以便继续编辑。其他组级错误保留设置中心的全局汇总。已有嵌入配置标识使用只读，新配置标识仍可编辑，保存期间整个编辑区禁用。

[表单组件夹具](../tests/renderer/fixtures/form-fields-gallery.tsx)与[Electron 回归](../tests/renderer/form-fields.test.mjs)使用当前 CSS；覆盖浅深主题、两种密度、桌面与窄容器、键盘和错误关联。截图仅在设置 `ROC_UI_AUDIT_DIR` 时输出，审阅后清理。合成 composition 事件验证守卫逻辑，系统中文输入法和 VoiceOver 仍需要人工实机验收。

### 页头、数据区与标准条目（2026-11-23 P1.3）

`shared/page-ui.tsx` 只提供页面组合：`PageHeader` 展示一级标题、真实摘要和一个主要动作；`PageSection` 用唯一标题关联数据区，次操作放在区块标题旁；`PageListRow` 是完整的原生按钮，分为标题、说明、装饰图标和尾部状态。窄容器自动换行，长中文标题和连续字符均可断行，使用现有字号、间距与状态 token。

列表拥有者仍负责稳定对象 ID、选中状态、方向键导航和虚拟化；条目透传 `ref`、`tabIndex`、ARIA、`disabled` 与原生表单属性，默认 `type="button"`。不要在条目内部嵌套按钮、链接或表单控件。列表行的 hover、active 和可见焦点不依赖颜色传达当前对象；选中语义由调用方使用 `aria-current` 等实际语义提供。

信息状态继续使用 `EmptyState` 与 `ErrorBar`，无需第二套异步状态组件。每个区块根据自身真实数据展示正常、空、加载、错误或受限状态；保留可用内容和对应恢复入口，不把局部错误升级为整页不可用。

### 项目入口与工作台（2026-11-23 P3）

项目入口复用 `PageHeader`，完整列表最多两列，卡片标题使用现有 16px 阅读字号。初次空态只有一个新建主操作，最近项目保留三个紧凑入口。列表初次挂载 40 项，每次“显示更多项目”增加 40 项并聚焦首个新增项目；搜索、状态筛选和计数始终基于完整项目集合，不能只搜索已挂载项。方向键、Home/End 可到达完整列表中的真实项目 ID，切换筛选时恢复首项。

工作台按“项目目标与主操作 → 当前研究 → 待我处理 / 近期成果 → 近期文献与快捷操作”组织；宽容器的待办与成果按 7:5 并列，窄容器顺序堆叠。长目标默认显示三行，展开按钮带 `aria-expanded` 与内容关联，键盘可切换。成果按后端真实类型显示图标与类型文字，并使用既有稳定 artifact ID 打开检视器。

主操作只导航到助手或任务详情：无当前任务为“开始研究”，运行中为“查看运行”，审批中为“处理审批”。只有当前任务诊断明确提供 continuationRunId、没有待恢复审批且没有清理失败时，才显示“继续研究”；该按钮仍需在任务详情核对后执行，不自动启动或恢复运行。任务状态、原因、完成阶段和更新时间来自真实数据；项目阶段明确标作“项目阶段”，不能冒充任务执行阶段。

任务摘要只读取近期 25 项；`hasMore` 时显式说明范围，空态使用“近期任务中没有”，并保留全部任务入口。当前会话契约没有项目归属字段，因此工作台不伪造项目“最近会话”。[项目入口回归](../tests/renderer/project-session-layout.test.mjs)覆盖 0 / 1 / 100 项、完整搜索和稳定键盘选择；[工作台回归](../tests/renderer/project-overview.test.mjs)覆盖导航边界、真实原因与成果类型、部分历史、目标展开和主题密度。

### 写作目录与构建问题（2026-11-23 P5）

文件树和写作列表复用 `workspace/directory-index.ts`，同一 client 与工作目录的同一目录请求只执行一次；共享待完成请求与目录元数据，不缓存文件正文。文件树仍按展开意图惰性读取，写作列表仍只读取根与一级目录，保留后端截断和部分失败提示。最后一个消费者离开时取消 watcher、合并计时器并清空索引；重新进入后读取磁盘，避免无人监听期间的数据过期。收到其他工作目录的返回结果时明确失败，不能将其显示在当前项目。

外部修改的首个事件立即失效并刷新，200ms 内后续事件按全部受影响路径合并；目录重命名同时失效已缓存的子目录。手动重扫与保存后的元数据刷新走相同失效通路。隐藏写作暂停目录订阅与全局保存快捷键；重新显示只刷新文件元数据，草稿与导航保护仍保留。写作的目录刷新不重置正文或草稿；组件仍通过既有加载序列拒绝旧返回覆盖新结果。

编译主文件、取消、结果、PDF 预览与导出保留在顶部工具栏；诊断移到编辑区底部的“构建问题”面板。失败时默认展开，总高 160–240px，内容独立滚动；收起后只保留可键盘操作的标题与真实问题数。每条问题显示图标、文字严重级别、后端给出的文件/行号和原因，缺失位置不伪造行号。点击位置沿用草稿关闭保护和 CodeMirror 定位，编译失败不覆盖草稿。并排预览时源码区域占编辑/预览可用宽度的至少 55%。

[共享目录单测](../tests/unit/renderer-directory-index.test.mjs)覆盖请求合并、旧响应、工作目录隔离、子目录失效、失败恢复与订阅释放；[写作交互回归](../tests/renderer/authoring-tools-layout.test.mjs)覆盖真实组件共享读取、重挂载、外部修改保留草稿，以及构建问题展开/收起、错误行定位、取消和导出。系统编译器的实际可用性仍由离线编译测试和实机走查验证，界面夹具不替代编译运行证据。

### 壳控制职责（2026-11-23 P2）

`AppShellContent` 负责启动、主题、布局、快捷键与唯一窗口的组合。`use-app-route.ts` 继续作为导航控制层和唯一 URL 写入点，所有 Back/Forward、原生菜单及页面打开仍通过现有导航守卫；不因目录命名再建第二份路由状态。

- `workspace-controller.ts` 创建共享项目资源、目录绑定和唯一文献 store，提供实际已绑定的工作路径、项目可写性与概念快照。
- `panel-controller.ts` 管理搜索、管理面板、首次步骤和对象打开命令；保留 artifact 阅读位置、review/Git 草稿 Map 以及各自守卫。文件请求、文献定位 nonce 和任务选择在已接受的导航回调中提交，延迟动作通过当前 routeRef 检查项目身份。
- `run-attention-controller.ts` 消费已有任务中心，管理所选会话、助手草稿交接、运行提示与首次挂载；它不创建第二份任务业务状态，也不启动或恢复运行。切项目清除会话选择和运行提示，管理操作与正文选区只交接输入。

控制模块只负责状态与动作，重组件仍由原懒加载入口挂载；编辑草稿继续由领域 store / draft Map 持有，面板收起不会替换这些所有者。布局持久化继续独立于领域资源，按项目与模式读取；UI 偏好重置和快捷键使用同一组布局操作。

| T1 检索入库 | 新建项目 → 工作台 → 发现 → 搜索 → 选入文献 → 查看阶段 → 处理失败 | 能区分论文信息、PDF、解析、索引与知识页；来源部分失败保留结果；回执可定位 |

先做与改动直接相关的检查，不为静态样式增加镜像实现的单测。路由迁移、阶段事实、草稿保护和任务动作需要行为回归；正常路径通过后，只有新增风险或失败才扩大测试范围。

- 静态与构建：`pnpm typecheck`、相关 renderer 测试、`pnpm check:renderer-chunks`，确认重模块仍懒加载。
- 设计规则：运行 `pnpm audit:design` 扫描 renderer；单独目录用 `python3 scripts/ui-audit/audit-design-rules.py <目录>`，并人工复核误报及未覆盖规则。审计脚本、来源摘要与 MIT 许可固定在 `scripts/ui-audit/`，干净检出不依赖本机 Skill 安装。
- 实窗：1184/1280/1440px、浅/深主题、键盘、真实滚轮、IME、长标题、缩放；检查主内容无横向溢出，焦点可见且能返回。
- 裁切：在透明 Electron 窗口执行仓库内 `scripts/ui-audit/clip-audit.js`，传 `{ viewport: true }`；默认、hover、展开及动效最终落点均要求 `cut === 0`，`hidden` 人工复核。脚本只覆盖阴影，不替代焦点边界与实际截图检查。
- 真实性：真实服务不具备下载、解析、索引或模型能力时记录限制；fixture 只能证明展示和交互，不能证明 T1–T3 的外部执行成功。
- 用户研究：首次成功率、完成耗时、回退次数、状态识别率和 SUS 必须来自同意参与的目标用户。自动化检查不替代样本和录屏，也不自动达成灰度发布门槛。
