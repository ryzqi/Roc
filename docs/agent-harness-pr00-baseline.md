## Budget, effect, event and storage behavior

- `RunBudgetLedger` in `src/main/services/deep-agent/run-budget-ledger.ts:40-258` is durable per root run and transactionally checks deadlines, idempotency/input drift, model/tool/child counts, concurrency and token limits. The current baseline defaults have no total-token, cost or deadline cap; model calls 100, tool calls 500, child tasks 8, concurrent children 2, models 4 and tools 4. Model-call reservation uses the context-window size because output usage is not known yet; absent provider usage settles as unknown. Setting `maxCostUsd` currently fails with `run_cost_estimate_unavailable` because there is no price table. Startup changes reserved calls to unknown.
- `RunBudgetObserver` in `src/main/services/deep-agent/run-budget-observer.ts:9-49` reserves at model start and settles provider usage, error or unknown. The deterministic harness includes budget model/token/unknown/restart/loop/cost/deadline/inbox/retry/concurrency/window/child-tool scenarios. It does not measure a real provider or actual cost.
- `AgentToolEffectStore` in `src/main/services/deep-agent/tool-effect-store.ts:113-170` records reserved, in-progress, succeeded/failed states and input hashes. On restart, reserved becomes `failed_retryable`; in-progress becomes `unknown`. Reconciliation from unknown needs explicit 1–4000 character evidence and a result for `applied`, recorded transactionally. The external effect and local SQLite transaction are not atomic.
- `src/main/plugins/agent/chat-run-event-queue.ts` defaults to 1,000 queued events and merges text up to 8,192 characters; overflow aborts with `chat_run_event_queue_overflow`. `src/main/plugins/agent/run-event-log.ts:16-163` assigns cursor and writes event transactionally, trimming each run to 10,000. `listRunEvents` returns rows after a cursor without explicit replay-gap metadata. `restoreFrom` swallows source-query and per-row errors.
- `publishChatRunEvent` in `src/main/plugins/agent/runtime.ts:925-947` attempts persistence before event-bus publication, but persistence is best-effort and failures are logged. Event rows, checkpoints and run snapshots are not one atomic transaction. `session-repository.ts` has a separate transaction for completion events, acceptance events and run state; this does not make all runtime events durable.
- The SQLite schema in `src/main/infrastructure/database-schemas.ts` includes agent runs/threads/events/cursors, outbox, inbox, leases, telemetry, notification metrics, pending interrupts, LangGraph checkpoints/writes, tool effects/reconciliations, budget calls, tool progress, harness revisions, task contracts, pilot runs, context artifacts and task outbox cursors. Research persistence includes artifact content/metadata, claim revisions/claims, document parses/documents, embedding configuration (secret key reference) and evidence. Research workspaces also store source and generated files; truncated shell output may be retained as tee artifacts. These rows/files and external MCP/provider state do not share one transaction boundary.

## PR-00 result and handoff

PR-00 records the reproducible check state, execution/storage boundaries, recovery ordering, current failures and test locations. The most urgent follow-up is PR-01's shell-grant boundary: derive trusted workspace and an explicit versioned grant in the main process, default-deny absent/invalid grants, and authorize immediately before spawn. Validate only with isolated temporary data and include target-macOS evidence; the current `execution-isolation` fixture failure is not evidence of production sandbox behavior.

Additional PR-02 handoff risks are the research-role and context-summary model calls without explicit budget observer wiring, the lack of a price source for `maxCostUsd`, and the absence of a direct provider-usage propagation test. PR-03/PR-05 must preserve the distinction between local transactional effect/event records and remote side effects/checkpoints.
